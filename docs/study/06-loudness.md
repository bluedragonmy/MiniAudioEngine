# 第 6 關：響度表（LoudnessMeter）

檔案：`cpp/src/LoudnessMeter.cpp`

## 原理

LUFS 是 **ITU-R BS.1770** 標準定義的響度，EBU R128 規定了怎麼套用。串流平台、電視台都用它。四個步驟：

```
輸入 ──▶ K-weighting ──▶ 平方 ──▶ 每 100 ms 取平均 ──▶ gating ──▶ LUFS
         (2 個 biquad)
```

### 1. K-weighting

模擬耳朵對頻率的敏感度，由兩個 biquad 串聯：

- **高頻架（shelf）**：2 kHz 以上 +4 dB，因為頭和耳朵的形狀讓我們對高頻比較敏感。
- **高通（RLB）**：約 40 Hz 以下衰減，因為耳朵對極低頻不敏感。

標準只給了 48 kHz 的係數。為了支援任意取樣率，程式用 libebur128（開源的標準實作）同樣的方法：從類比原型的參數（`f0`、`G`、`Q`）用雙線性轉換（`K = tan(π·f0/fs)`）算出係數。

### 2. 平方平均 → LUFS

```
LUFS = −0.691 + 10 · log10(平方平均)
```

`−0.691` 是一個校正常數，讓 997 Hz、0 dBFS 的正弦波剛好讀到 **−3.01 LUFS**（標準規定的參考值）。

### 3. Gating（兩道門）

整首歌的平均如果把安靜的段落也算進去，會被拉低。所以：

1. **絕對 gate**：先丟掉 −70 LUFS 以下的區塊（幾乎無聲）。
2. **相對 gate**：算剩下的平均，再丟掉比平均低 10 LU 以上的區塊。

區塊長 400 ms，每 100 ms 一個（重疊 75%）。程式先存每 100 ms 的平方平均到 `blocks`，再每 4 個組成一個 400 ms 的 `gatingBlocks`。

### 4. 立體聲

左右聲道各自 K-weighting 後，**能量相加**（權重都是 1.0）。所以同一個訊號放在兩個聲道，會比只放一個聲道多 3.01 dB。

## 程式碼導讀

| 位置 | 在做什麼 |
|---|---|
| 建構子 | 算兩組 K-weighting 係數；右聲道複製同樣的濾波器 |
| `addEnergy()` | 累積 100 ms，存進 `blocks`；每滿 4 個就產生一個 gating 區塊 |
| `momentary()` | 最近 4 個 block（400 ms） |
| `shortTerm()` | 最近 30 個 block（3 s） |
| `integrated()` | 兩道 gate |

## 測試在驗證什麼

| 測試 | 意義 |
|---|---|
| `997 Hz 0 dBFS sine = -3.01 (48k)` | **標準的參考值**。這個過了，代表 K-weighting 和常數都對 |
| `-20 dBFS sine = -23.01` | 音量 −20 dB，LUFS 也剛好 −20 |
| `same at 44.1 kHz` | 任意取樣率的係數換算正確 |
| `relative gate ignores quiet part` | 5 秒大聲＋5 秒很小聲，結果約 −3.1 而不是 −6。**這也是我一開始預期寫錯的地方**：交界處的幾個區塊「半大聲」，會通過 gate，所以稍微拉低一點，這是正確行為 |
| `same sine in L and R = 0.00` | 立體聲：兩個 −3.01 相加 = 0.00 |
